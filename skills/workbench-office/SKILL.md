# Office 文件交付

先确认用户要求的文件格式、输入资料、模板和可编辑性。保留输入原件，在工作区创建输出。发现并加载宿主已提供的格式技能：当前官方 DSH 使用 `office-docx`、`office-xlsx`、`office-pptx`，独立渲染、重算和 PDF 导出分别使用 `office-render`、`office-recalculate`、`office-export-pdf`。通过当前可用的 `skill` 工具加载，不重复安装同类工具。

遵循已加载技能提供的实际运行环境和资源路径。导出格式应与内容匹配：用户要可编辑 PPTX，就生成真实 PPTX；仅生成 HTML 或把后缀改成 `.pptx` 不构成该交付。

## 按文件类型验收

| 类型 | 内容与行为检查 | 需要视觉检查时重点查看 |
| --- | --- | --- |
| Word / PDF | 标题、正文、表格、引用与输入资料一致；文件能重新打开或解析 | 分页、表格跨页、截断、字体、页眉页脚 |
| Excel | 源数据行数、单位、汇总、公式和缓存值；重算后无公式错误 | 数字格式、列宽、图表标签、打印区域 |
| PowerPoint | 页数、叙事顺序、数据、引用和要求的可编辑元素 | 文字溢出、遮挡、对齐、对比度、图片裁切 |

涉及排版、页面设计、图表展示，或用户要求可直接汇报/发布时，渲染最终版本并检查各页。用户明确要求跳过渲染时遵从并说明检查范围；单纯数据修改可优先验证数据与公式。视觉模型输出属于辅助证据，重要数字仍回到源数据核验。

使用 `workbench_plan` 时将“生成文件”“数值或内容正确”“视觉检查”分开。机器校验通过 `workbench_verify` 留下退出状态和输出；将最终文件、检查记录及必要预览登记为产物。文件存在证据只用于存在标准，内容和排版标准须保留实际检查依据。修改后重新生成相应预览和登记哈希。

缺少作者工具、渲染器或字体时，先完成可独立处理的数据与内容，记录具体缺项及安装说明。交付清楚标记哪些检查已执行、哪些待执行，不把创建空文件当成已完成。
