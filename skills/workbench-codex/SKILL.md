# Codex 协作

检查当前会话是否暴露 `codex_start`、`codex_status`、`codex_cancel`。可用时通过 `workbench_doctor` 查看本机 Codex 发现结果，再按需启动任务。桥接需要本机 Codex 运行环境和可用登录；插件存在并不证明模型连接成功。不要读取或复制登录凭据。

## 明确任务包

委派提示词应包括：目标、当前工作区中的相关路径、允许修改范围、已确认事实、验收标准、需返回的文件与验证结果。只提供完成子任务所需材料，避免发送无关的整个会话。对于复杂开发可先安排只读分析，再明确授权修改。

`codex_start` 使用 `prompt`、`mode` 和可选 `model`、`taskId`。以工具实际枚举为准，默认只读；写入需要宿主已启用写模式并允许当前操作。未指定模型时使用本机已有配置，不自行猜测或升级模型。提示词由桥接送入标准输入，无需拼接终端命令。

启动返回的是作业记录而非完成结果。保存 `job.id`，通过 `codex_status` 查询退出状态、最终回答和事件记录。等待期间可处理不冲突的工作；避免另一个代理修改 Codex 正在处理的文件。用户要求停止时调用 `codex_cancel`，核对作业已终止。

## 接回与验收

成功退出后，查看真实修改、最终文件和测试输出，核对是否满足委派范围。把产物登记到父任务；需要时用 `workbench_verify` 在当前环境独立检查关键标准。模型自述、退出码 0 和空的最终回答均不足以证明用户目标已完成。

失败、超时或取消后读取现有记录，检查工作区可能留下的修改，再决定继续、修复或保留结果。恢复任务要引用已保存进度，不重复执行有外部效果的动作。接口或登录问题需要外部修复时，清楚说明具体失败阶段；路线一仍能继续独立任务。

这个桥接把任务交给真实 Codex 进程，不迁移 Codex 桌面应用的全部连接器、界面或账户能力。调用会使用现有 Codex 账号与相应额度。
