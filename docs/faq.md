# 常见问题

## 这是 Codex Desktop 的替代品吗？

不是。项目通过本机 Codex CLI 提供一个有边界的协作入口，不复制 Codex Desktop 的界面、连接器、登录态或订阅额度。

## 为什么任务完成了还需要验收？

Codex 或 DSH 进程正常结束，只能说明本次执行完成。文件内容、数据准确性、页面布局和业务规则仍必须由真实检查程序或人工检查确认。

## 工作区记录放在哪里？

任务账本和 Codex 日志放在项目工作区的 `.dsh-workbench/`。该目录默认被 Git 忽略，适合本地追踪，不会随项目源代码提交。

## 为什么 `npm test` 有 skipped？

未设置 `DSH_HOST_NODE_MODULES` 时，依赖本机 DSH 安装的原生 schema 检查会跳过，其他离线测试仍会运行。设置该变量后可执行完整的 DSH 原生接口检查。

## 如何开启 Codex 写模式？

先在 DSH 插件设置中将 `allowCodexWrite` 设为 `true`，再确认工作区可写，并在每次启动时通过 DSH 原生审批。默认仍建议先使用 `read-only` 分析。

## 如何卸载或恢复？

常规卸载使用 DSH 插件管理页面。若需要恢复安装前 profile 文件，使用安装脚本生成的备份路径运行 `scripts/rollback.mjs`；脚本会检查后续手工修改，避免覆盖新内容。

## 遇到问题需要提供什么？

请提供 Node.js 和 DSH 版本、运行命令、完整错误摘要、是否使用真实 DSH 依赖，以及脱敏后的 `.dsh-workbench/` 状态。不要上传 token、密钥、个人数据或完整工作区。
