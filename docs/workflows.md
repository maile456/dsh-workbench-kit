# 使用工作台完成真实任务

本项目提供任务账本、证据记录、成果检查和 Codex 协作入口。搜索、视觉、记忆与 Office 使用当前 DSH 已安装并启用的工具；不会自动重复安装第三方插件，也不声称完整复制 Codex 桌面能力。

## 六套技能

| 技能 | 何时使用 | 交付关注点 |
| --- | --- | --- |
| [workbench-delivery](../skills/workbench-delivery/SKILL.md) | 多步骤任务、长任务、跨会话续做 | 标准、状态、真实证据、文件身份 |
| [workbench-research](../skills/workbench-research/SKILL.md) | 查资料、比较方案、研究报告 | 原始来源、日期、事实与推断 |
| [workbench-coding](../skills/workbench-coding/SKILL.md) | 实现功能、修 bug、代码审查 | 仓库约定、真实行为测试、最终 diff |
| [workbench-office](../skills/workbench-office/SKILL.md) | Word、Excel、PowerPoint、PDF | 格式有效、数据核对、公式与布局 |
| [workbench-browser](../skills/workbench-browser/SKILL.md) | 网页读取、表单和浏览器测试 | 新鲜页面状态、实际操作结果 |
| [workbench-codex](../skills/workbench-codex/SKILL.md) | 用户允许的 Codex 子任务 | 范围、访问模式、后台状态、接回验收 |

插件挂载成功后，DSH 会发现这些技能。调用时使用当前会话实际提供的技能入口；技能文件也可直接阅读。[能力目录](../catalog/capabilities.json) 给出依赖与已核对的工具线索。

## 路线一：增强 DeepSeek 的交付流程

可向 dsh 发送：

> 用工作台整理本目录的销售数据，生成可编辑的 Excel 汇总和一份 Markdown 说明。先记录验收标准，再完成文件与数据核验。沿用已有工具。

合适的验收标准示例：

1. 指定路径的 XLSX 存在且非空。
2. 每个区域的销售总额与源数据重算一致。
3. 缺失值和重复记录的处理方式在说明中明确列出。

第一条可以由文件登记检查支持；第二条应运行读取源文件与输出文件的核对脚本；第三条应检查真实数据处理结果和说明内容。登记一个存在的文件不能替代第二、第三条。

任务工具的配合关系：

- `workbench_plan` 建立任务，输入标题、目标和标准列表，保留返回的任务 ID。
- `workbench_status`、`workbench_list` 读取进度；`workbench_update` 记录状态与下一步。
- `workbench_verify` 执行验证程序，记录标准编号、参数、输出和退出状态。
- `workbench_artifact` 登记工作区中的真实产物及其哈希。
- `workbench_complete` 检查证据与产物是否齐全，并重新核对文件哈希。

验证命令按“可执行文件 + 参数数组”传递。把检查做成项目中的脚本比拼接一段 shell 更方便复现。语义检查必须真的读取和核对成果；一个永远退出 0 的脚本无法形成有效验收。

## 路线二：dsh 调度 Codex

可向 dsh 发送：

> 允许使用本机 Codex，只读分析这个项目的登录流程并给出修复建议。把结果记录到工作台，暂时不改源代码。

桥接启动会立即返回作业记录。用 `codex_status` 查看运行中、成功、失败、超时或取消状态，使用 `codex_list` 找回作业，使用 `codex_cancel` 停止。只有实际终止状态、日志和产物支持的结论才能进入父任务验收。

需要修改项目时另行明确修改范围；插件的写模式配置和宿主授权都应允许。Codex 使用本机已有模型登录与配置，真实运行可能消耗相应额度。此项目不替换登录，也不把 Codex 桌面的连接器自动导入 dsh。

## 诊断结果应如何理解

“已发现软件包”“当前会话已有工具”“工具实际调用成功”是三个不同状态。`workbench_doctor` 的静态发现只用于定位安装线索，不能证明搜索引擎、视觉服务、浏览器登录或 Codex 模型已就绪。

例如：搜索插件已装好，但提供方可能已耗尽额度；视觉工具已注册，但配置的模型可能不可达；浏览器侧栏能显示页面，但控制连接尚未建立。遇到这些情况记录具体缺项，继续可独立完成的步骤。

## 恢复工作

保留工作区的 `.dsh-workbench/`。重新打开项目后让 dsh 查询任务清单，再读取相应任务与真实文件。已经变更的产物应重新登记并重跑受影响检查。中断、失败和取消都不自动撤销工作区中的修改；决定重试前先查看现状。

任务账本与日志可能包含项目内容，按项目自身的数据管理要求保存；长期记忆中仅保留稳定决定，不额外复制完整执行日志。
